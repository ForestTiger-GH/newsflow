# newsflow — Workspace Passport

## Engineering Subject

Development of `newsflow` as a compact public-web observation and source-discovery system that can turn changing internet sources into durable, provenance-aware, agent-readable inputs without collapsing discovery, source preservation, qualification, downstream admission, derivation, or analysis into one layer.

This file is a routing projection. It does not own Product truth, Research conclusions, source evidence, or downstream repository state.

## Mandatory cold entry

For every distinct material Work in this repository:

1. open the root `README.md`;
2. explicitly open this file;
3. resolve the active Development Epoch below;
4. open only the epoch/research material required by the commissioned Work;
5. treat prior conversation or model context as discovery-only until rebound to a current repository route or source.

If the task is to change the Work architecture or physical workspace structure, use the MADARAII-01 / MADARAII-02 bootstrap semantics rather than improvising layout.

## Resolution policy

Resolve material inputs by:

```text
semantic role + reason
→ authoritative route or stable identity
→ intended current revision / Baseline
→ scope, integrity, currentness, access, and reliance checks
→ least-sufficient read closure
```

Filename similarity, directory proximity, search rank, or model memory may discover candidates but do not establish Authority or currentness.

## Authority and admission

- The repository owner supplies or delegates the Commission for material Work and workspace change.
- An agent may inspect, research, or mutate only within the commissioned boundary.
- A discovered web item does not become accepted source evidence, Tabularium content, Product truth, or analytical truth merely because `newsflow` captured it.
- Physical placement does not change semantic ownership or admission state.
- Material downstream admission requires the authority and contract of the destination system.

## Local artifact policy

- Create a durable artifact only when independent consumer, lifecycle, recovery, handoff, provenance, or review value justifies it.
- Research history is not maintained current knowledge.
- Source material, representations, observations, derivations, and analytical claims remain distinct when those differences affect reliance.
- Preserve `UNKNOWN != false != zero != not applicable`.
- Avoid speculative directory trees and premature schemas.
- Route-oriented README files are preferred over large duplicated descriptions.
